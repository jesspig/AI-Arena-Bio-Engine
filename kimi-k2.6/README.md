# Bio-Engine · Kimi-K2.6 实现

> 在代码中创造会呼吸的生命。

这是一个程序化生物动画系统，不是播放预制的动画帧，而是让生物在每一帧都根据物理规则、行为逻辑和环境交互**实时决定自己该怎么动**。你看到的每一次扭动、每一步行走、每一次转向，都是算法当场计算出来的。

---

## 在线体验

```bash
bun install
bun run dev
```

打开浏览器，你会看到一只发光的脊椎生物在深色空间中漫游。移动鼠标，它会感知你的存在——靠太近它会逃跑，保持一定距离它会好奇地靠近。

## 设计灵感：深海发光生物

这个视觉风格来源于我对深海生物的想象——在完全没有光线的环境中，生物进化出了自己产生光的能力。它们的发光不是为了照亮什么，而是为了交流、为了表达状态、为了在黑暗中确认彼此的存在。

我选择的不是写实风格，而是**科幻霓虹感**的表达：

- 深色背景让发光效果更突出
- HSB 色彩空间让色调变化流畅自然
- 多层半透明光晕模拟生物发光器官
- 粒子拖尾像是生物在黑暗中留下的信息素轨迹

## 核心功能

### 程序化脊柱运动

生物的身体由 18~36 个节段组成，采用**位置插值跟随法**实现链式运动：

- 头部根据行为目标决定移动方向
- 每个后续节段朝前一节段的上一帧位置平滑插值移动
- 插值系数（followFactor）控制在 0.3~0.4 之间，既保证跟随的紧密性，又保留自然的惯性延迟

这种算法的优雅之处在于——**不需要物理模拟就能产生类似物理的惯性效果**。节段越多，尾巴的甩动越慵懒；插值越小，跟随越迟缓。这些参数本身就是性格的表达方式。

### 简化的肢体 IK 与步态

每条腿都是一个二关节链，使用**解析法 IK** 直接计算膝关节位置：

- 已知根部位置和脚的目标位置
- 用余弦定理和几何关系一次求解，没有迭代开销
- 配合脚的"吸附/释放"逻辑：脚在地上时保持不动，身体移动超过阈值后抬脚迈向新位置

抬脚过程中加入正弦弧线模拟抬腿高度，落地时直接定位到目标点。这种简化虽然不如完整物理模拟精确，但计算极快，且视觉上足够 convincing。

### 行为状态机

生物不是随机乱动，它有四种状态：

| 状态 | 行为 | 速度 |
|------|------|------|
| **Idle（ idle）** | 缓慢原地摆动，像在休息 | 30% |
| **Roam（漫游）** | 随机选择目标点移动 | 100% |
| **Chase（追逐）** | 被鼠标吸引，朝鼠标移动 | 180% |
| **Flee（逃离）** | 鼠标太近，快速逃跑 | 220% |

状态切换不是硬切的——每个状态有持续时间，时间到了才会重新评估。鼠标的存在会强制覆盖当前状态，创造出"生物在注意你"的感觉。

### 粒子系统

两种粒子增强氛围：

- **尾部拖尾粒子**：从生物尾部不断释放，随时间扩散消失，像是生物在虚空中留下的痕迹
- **关节闪烁粒子**：沿脊柱随机生成，向上飘动，模拟生物发光器官的脉动

粒子数量受发光强度参数控制，不同生物有不同的"亮度"。

### 呼吸光效

每个生物有一个独立的脉冲相位，用正弦波控制整体发光强度的周期性变化。配合不同生物的随机初始相位，创造出各自独立的"呼吸节奏"。

## 架构设计：引擎与渲染分离

```
引擎层（纯算法，零外部依赖）
  ├── types.ts     — 所有数据结构定义
  ├── math.ts      — 向量运算工具库
  ├── creature.ts  — 生物创建、脊柱跟随、肢体IK、行为状态机
  ├── particles.ts — 粒子生成与生命周期管理
  └── world.ts     — 世界状态管理、生物增删

渲染层
  └── renderer/p5Renderer.ts — p5.js 画布渲染（网格、粒子、生物轮廓、光晕、头部）

UI/交互层
  ├── components/BioCanvas.tsx    — p5 画布挂载、鼠标/触摸事件转发
  ├── components/ControlPanel.tsx — 添加/清除生物、状态显示
  └── components/InfoOverlay.tsx  — 底部信息层
```

**关键原则**：引擎层不调用任何绘图 API，只通过纯函数接收数据、返回数据。这意味着引擎可以独立测试，也可以被移植到任何其他渲染框架（Canvas 2D、WebGL、Three.js 等）而无需修改。

## 为什么这样设计

### 为什么选择位置插值跟随，而不是距离约束或弹簧物理？

- 距离约束需要多次迭代才能达到稳定效果，计算开销更大
- 弹簧物理虽然真实，但参数调不好容易产生抖动或过度弹性
- 位置插值在计算简单和运动自然之间取得了最佳平衡，而且**惯性效果可以通过调整插值系数直接控制**

### 为什么用解析法 IK，而不是 FABRIK 或数值迭代？

- 每条腿只有两个关节，解析法一次得解，O(1) 复杂度
- FABRIK 需要多次迭代，对于二关节链是过度设计
- 数值迭代法更灵活，但这里不需要处理复杂约束

### 为什么状态机只有四种状态？

- 更多状态意味着更复杂的切换逻辑和更多的调试工作
- 四种状态已经能表达出"有生命"的感觉：休息、探索、好奇、恐惧
- 状态的组合（比如漫游时突然被惊吓）本身就创造了丰富的行为变化

### 为什么粒子系统这么简单？

- 粒子没有碰撞、没有力场，只有位置和生命周期
- 这种简化让系统能轻松支持数百个粒子而不掉帧
- 视觉上的氛围感不需要物理精确，只需要**足够多的微小光点**

## 可探索的方向

如果你想在这个基础上继续玩：

- **改参数**：调整 `followFactor` 让生物更僵硬或更柔软，调整 `segmentCount` 创造短粗或细长的生物
- **加多生物**：点击"添加生物"，观察它们各自独立的行为和偶然的路径交叉
- **换颜色**：修改 `colorHue` 范围，从深海蓝变成岩浆红或森林绿
- **改交互**：让生物之间互相吸引或排斥，创造群体行为
- **加声音**：根据生物状态播放不同频率的环境音，创造沉浸感
