## 它是什么

这是一个**完全由程序驱动生成的虚拟生物**。没有预制动画，没有关键帧，没有 sprite sheet。它的每一次蜿蜒、每一步行走、每一个呼吸，都是数学公式实时计算的结果。

它有 18 节脊椎、6 条腿、两只竖瞳，以及一套简单的情绪系统。它会在画布上自由漫步，会对你的好奇做出回应，也会在你逼近时惊慌逃窜。

**这不是游戏，不是动画，是一次关于"代码能否创造生命感"的实验。**

---

## 设计灵感

### 从一条蛇开始

最初的灵感来自蛇的运动。蛇没有腿，但它的身体本身就是最好的运动工具——波浪从头传递到尾，每一片鳞片都在地面上施加微小的力。这种「链式跟随」（chain following）的运动方式，是程序化动画中最优雅的起点之一。

但纯蛇形太常见了。我想做的是——**给蛇加上腿**。

### 当蛇有了腿

想象一只蜥蜴。它的脊椎保持蛇形的蜿蜒，但每一条腿都独立地在地面上寻找支撑点。身体向前推进时，腿要么牢牢抓住地面提供反力，要么抬起迈出下一步。这种**脊椎提供推进力、腿提供支撑力**的协作，是四足/六足动物运动的核心机制。

而更有趣的是——当你把这种机制交给代码而不是手绘师，**运动的"瑕疵"反而成了生命力的来源**。腿偶尔抬得不够高、转弯时身体略微打滑、停下来时尾巴还在惯性中摆动……这些不是 bug，是 character。

### 赋予意图

一个只有物理没有意志的生物，只是一个机械装置。为了让它真正"活"起来，需要给它一套**行为系统**——它想去哪里？它对什么感兴趣？它什么时候害怕？

我选择了最简单的模型：一个有限状态机。四种状态——**休息、漫步、好奇、逃离**——之间通过条件切换。配合 Perlin 噪声生成的方向变化，漫游路径不会是锯齿形的折线，而是像真实动物那样平滑、有机、偶尔迂回。

## 实现了什么

### 脊椎系统

```
头部 → [18 个节段] → 尾尖
  ↑                   ↑
 宽 16px            宽 ~5px（渐变收窄）
```

- **算法**：距离约束迭代法（3 次迭代/帧）
- **18 个节段**，每个有独立的位置、角度、宽度
- 宽度从头部 16px 线性收窄到尾部约 5px
- 每帧头部朝目标移动，其余节段通过约束保持固定间距
- 身体自然形成蜿蜒曲线，无需手动计算弯曲

### 肢体系统

```
脊椎[3] ← 前左腿    脊椎[3] ← 前右腿
脊椎[7] ← 中左腿    脊椎[7] ← 中右腿
脊椎[12] ← 后左腿   脊椎[12] ← 后右腿
```

- **6 条腿**，每条有上臂（22px）+ 前臂（24px）两个关节
- **二关节解析 IK**：用余弦定理直接求解膝关节位置
- **足部吸附/释放机制**：
  - 脚在地面上时完全不动（isPlanted = true）
  - 当身体移动导致脚距自然位置超过 70% 腿长时，脚抬起
  - 抬脚动画用 ease-in-out 缓动 + 正弦弧线
  - 落地后立即吸附，开始下一轮等待
- **左右交替**：相邻脊椎节段的腿共用锚点但膝关节方向相反

### 行为系统

| 状态 | 触发条件 | 行为 |
|------|----------|------|
| 🟢 漫步 | 默认/定时器耗尽 | Perlin 噪声驱动方向，平滑转弯 |
| 💤 休息 | 漫步结束 30% 概率 | 停止移动，等待 1-3 秒 |
| 👁 好奇 | 鼠标靠近（<200px） | 朝鼠标移动，到达后减速观察 |
| ⚡ 逃离 | 按住鼠标且靠近 | 全速远离，方向背离鼠标 |

- 状态切换时**重置定时器**，避免频繁抖动
- 漫游方向用 `noise2D(time, 0)` 和 `noise2D(0, time)` 采样，保证连续性
- 边界约束：所有目标点强制 clamp 到画布内 50px margin

### 渲染系统

**身体**：
- 左右两条边缘点构成封闭形状
- 颜色沿脊椎三段渐变：翠绿 `#2dd4a0` → 深绿 `#1a9e6f` → 墨绿 `#0d5e3a`
- 菱形鳞片纹理：每隔一个节段，在身体两侧绘制旋转 45° 的菱形

**头部**：
- 椭圆主体 + 三角形吻部 + 鼻孔
- 眼睛：白色底 + 琥珀色虹膜 + **垂直瞳孔**（爬行动物特征）
- 瞳孔会根据状态变化：逃离时变细变长（应激反应）
- 好奇时头顶出现"眉弓"弧线，逃离时鼻孔扩张
- 周期性眨眼动画

**呼吸**：
- 全身宽度随 `sin(breathPhase)` 微量脉动（±8%）
- 光晕半径同步脉动（±15%）
- 呼气时从口部喷出白雾粒子

**粒子系统**：
- **运动拖尾**：头部速度 > 0.5 时，沿运动反方向释放绿色粒子
- **呼吸白雾**：呼气相位时从口部释放，随头部朝向飘散
- 粒子带阻尼衰减（速度 ×0.98/帧），透明度随生命值线性下降
- 总粒子数硬限制：拖尾 80 + 呼吸 40 = 120

**环境**：
- 深色背景 + 缓慢漂移的网格线
- 30 个环境光点（"星星"），亮度随时间正弦变化

## 为什么这么设计

### 1. 引擎与渲染严格分离

```
engine/     ← 零绘图 API，纯数据 + 数学
renderer/   ← p5.js 绘图，读取引擎输出
components/ ← React UI，桥接两者
```

**为什么**：引擎层可以被任何渲染器消费——Canvas2D、WebGL、SVG、甚至终端字符画。如果明天要换掉 p5.js，只需要重写 renderer 层，engine 一行不动。

**代价**：每帧需要从引擎复制状态（spine 数组深拷贝），增加了少量开销。但对于 18 个节段 + 6 条腿的规模，这完全可以忽略。

### 2. 选择距离约束迭代法而非弹簧物理

弹簧物理更"真实"，但调参困难（刚度、阻尼、质量互相耦合），且容易出现数值不稳定（爆炸、抖动）。

距离约束迭代法：
- **只有两个参数**：节段长度、迭代次数
- 迭代 3 次已经足够收敛，视觉上与 10 次几乎无区别
- **天然稳定**：不可能出现节段飞出去的情况
- **可控性强**：头部位置精确等于目标点，不会被弹簧力"拉偏"

### 3. 二关节解析 IK 而非 FABRIK

每条腿只有两个关节（肩/髋 → 膝 → 足），二关节 IK 有闭式解（余弦定理），一次计算就得结果，不需要迭代。

FABRIK 更通用，但对于二关节情况是杀鸡用牛刀。解析解的计算量是 O(1)，6 条腿每帧只做 6 次三角函数。

### 4. Perlin 噪声而非随机目标点

随机目标点的问题：方向突变。生物会突然 180° 掉头，看起来像抽搐。

Perlin 噪声的特性：**连续输入 → 连续输出**。时间缓慢推进，方向缓慢变化。结果是平滑的弧线路径，像真实动物在巡视领地。

### 5. 状态机而非行为树

四种状态的切换逻辑只有 5-6 个条件判断。行为树适合有 20+ 行为的游戏 AI，但对这个规模是过度设计。

有限状态机的优势：
- 全部逻辑在一个函数里，一眼看完
- 状态切换条件是显式的，不会出现树遍历的隐式优先级
- 调试时只需看 `currentState` 就知道生物在"想什么"

```
│   │   ├── spine.ts               # 脊椎链式运动

│   │   ├── behavior.ts            # 行为状态机

│   │
│   ├── renderer/                  # p5.js 渲染层
│   │   ├── creatureRenderer.ts    # 身体/头部/腿/鳞片/粒子绘制
│   │   └── particles.ts           # 粒子发射与更新
│   │
│   ├── components/                # React UI
│   │   ├── BioCanvas.tsx          # p5 画布容器
│   │   └── ControlPanel.tsx       # 状态面板 + 调试开关
│   │
│   ├── App.tsx                    # 根组件
│   ├── main.tsx                   # 入口
│   └── index.css                  # Tailwind 导入
│
├── vite.config.ts
├── tsconfig.json
└── package.json
```

## 已知边界与未来可能

### 当前未实现的

- **多生物互动**：目前只有一只。引擎层已支持配置化创建多只，但 UI 层未接入
- **障碍物避让**：漫游路径不会绕过障碍，因为没有障碍
- **声音**：完全静音。呼气粒子可以配合呼吸音效
- **参数热调**：CreatureConfig 已设计为可 Partial 覆盖，但 UI 没有暴露滑块

### 如果要扩展

- **加一条蛇**：把 `legs` 配置清空为 `[]`，它就变成了纯脊椎蛇形生物
- **换视觉风格**：只改 `creatureRenderer.ts`，不动 engine
- **加触手**：在 `LegConfig` 上增加关节层数，IK 求解器从二关节扩展到 N 关节
- **联网多只**：把 `CreatureState` 序列化，通过 WebSocket 同步

## 写在最后

程序化动画最迷人的地方在于——**你定义规则，系统创造表演**。

你不会知道它下一秒会往哪走，不会知道它转弯时尾巴会甩出什么弧度，不会知道它停下来喘气时瞳孔会缩到多细。这些都不是你"画"出来的，是数学"长"出来的。

这条蜥蜴不存在于自然界，但它有自己的呼吸、自己的节奏、自己的脾气。

这就够了。
