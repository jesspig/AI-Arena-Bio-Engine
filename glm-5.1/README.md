# 深渊螈 · Abyss Salamander

> *在代码的深渊中，一条会呼吸的生命正在苏醒。*

---

## 这是什么？

**深渊螈**是一只完全由程序生成的虚拟爬行动物。它不是手工绘制每一帧动画，而是由一套自洽的规则系统驱动——脊柱如何跟随、肢体如何迈步、情绪如何切换、身体如何发光——所有行为都从算法中自然涌现。

打开页面，你会看到一只浑身散发着幽蓝荧光的蝾螈，在漆黑的深水中缓缓游弋。它的身体蜿蜒摆动，四条腿交替着地行走，外鳃随呼吸轻轻摇曳。当你移动鼠标，它会感知你的存在；当你靠得太近，它会惊慌逃窜；当你点击画布，它会朝你游来。

**这不是一段预设的动画播放，而是一个活着的系统在实时运转。**

## 设计灵感

### 为什么是蝾螈？

在所有可能的生物形态中，蝾螈是一个绝佳的选择——它兼具蛇的柔韧和蜥蜴的四肢，既有链式脊柱的优雅曲线，又有肢体 IK 的技术挑战。更关键的是，深水蝾螈（如墨西哥钝口螈）天生就带着一种神秘的美感：半透明的皮肤、羽毛状的外鳃、在暗水中闪烁的微光——这些特征天然适合用程序化方式表达。

### 深渊美学

视觉风格选择了**深海生物发光**而非其他方向，原因有三：

1. **技术适配**：p5.js 的 HSB 色彩模式天然适合表达发光效果——低饱和度背景 + 高饱和度前景 + 透明度叠加，就能模拟出生物荧光的质感，无需着色器
2. **氛围营造**：深黑背景上的微弱光点自带沉浸感，用户不需要任何说明就能感受到"这是水下"
3. **情绪映射**：发光强度和色相可以随行为状态实时变化——惊吓时泛红、追踪时偏暖、平静时回归冷蓝——视觉本身就是情绪的指示器

### "错误"中的发现

身体宽度曲线的尾部使用了二次衰减（`s * s`），最初是无意中写出的。但观察效果后发现，这种加速收窄比线性衰减更像真实蝾螈的尾巴——从粗壮到纤细的过渡更加戏剧化。这正是设计文档所说的"在错误中发现"。

## 核心技术

### 脊柱系统：距离约束 + 角度约束的混合算法

脊柱是整个生物的骨架，24 节脊椎决定了身体的形态和运动。

**为什么不只用一种约束？**

- 纯距离约束（思路 A）能产生自然的跟随效果，但身体可以像绳子一样任意弯折，看起来不像有骨骼的生物
- 纯角度约束（思路 D）能控制关节弯曲幅度，但缺乏整体的连贯感

**混合方案**：先做 4 轮距离约束迭代让身体自然跟随，再做角度约束确保相邻脊椎的弯曲不超过 63°（`MAX_BEND_ANGLE = π × 0.35`）。这样身体既柔韧又不失骨骼感——蛇的流畅 + 蜥蜴的结构。

身体宽度采用三段式曲线：头部（14px）渐宽到中段（18px），中段保持粗壮，后半段以二次曲线收窄到尾部（2px）。这个轮廓让深渊螈看起来像一个有体积感的实体，而非一串圆点。

### 肢体系统：解析 IK + 吸附释放步态

四条腿分别附着在脊柱第 3 节和第 9 节，前肢略长于后肢，模拟蝾螈的身体比例。

**二关节解析 IK**

每条腿由大腿和小腿两段组成，使用余弦定理直接求解膝关节位置——这是 IK 中计算量最小的方案。关键细节是 `bendSign` 参数：左侧腿膝盖向外弯，右侧也向外弯，这确保了自然的爬行姿态而非诡异的对称折叠。

当目标超出可达范围时，不是简单地伸直，而是将脚的位置钳制到最大可达距离处——这样即使在极限位置，肢体仍然保持合理的弯曲姿态。

**吸附-释放步态**

这是让生物"真的在走路"的关键机制：

1. 脚着地时（`isPlanted = true`），脚的位置固定不动，身体从脚上方移过
2. 当臀部与脚的距离超过阈值（50px），脚"松开"并开始移动
3. 新脚位 = 臀部位置 + 运动方向前方的偏移，步幅与移动速度成正比
4. 移动过程使用缓入缓出插值（`easeInOutQuad`），12 帧内完成一步

这个机制让四条腿自然地交替运动——前腿先迈、后腿跟随——无需显式编写步态协调逻辑，步态从物理约束中自然涌现。

### 行为系统：四状态有限状态机

深渊螈有四种情绪状态，每种状态影响移动速度和目标选择：

| 状态 | 速度 | 持续时间 | 触发条件 | 视觉反馈 |
|------|------|---------|---------|---------|
| **漫游** | 1.2 | 2~5 秒 | 默认 / 从其他状态恢复 | 冷蓝发光 |
| **追踪** | 2.5 | 10 秒 | 鼠标在 300px 内 / 点击画布 | 暖色偏移 |
| **惊吓** | 4.0 | 1 秒 | 鼠标突然进入 80px | 红色闪烁 + 粒子爆发 |
| **休息** | 0.3 | 3~7 秒 | 漫游中 15% 概率 | 暗淡柔和 |

**设计决策**：为什么不用行为树或效用系统？因为这个项目的核心是视觉表现而非 AI 复杂度。有限状态机足够表达"一条蝾螈会做什么"，而且状态之间的切换条件清晰、可预测，方便用户理解因果关系——"我靠近了，它跑了"——这种直觉性的交互比复杂但不可读的行为更有价值。

**惊吓优先级**：惊吓状态可以在任何其他状态中打断触发（除了惊吓自身），这是唯一一个高优先级状态。这模拟了真实动物的本能反应——无论在做什么，危险来了先跑。

### 蛇形波动

在行为系统给出的速度方向上，叠加一个正弦横向偏移：

```
waveOffset = sin(time × 0.15) × 0.3
velocity = desiredVelocity + perpendicular(headAngle) × waveOffset
```

这个微小的横向摆动让直线移动也带有蛇行的韵律感。没有它，深渊螈在漫游时看起来像一辆小车；有了它，它像一条在水中游动的生物。

### 头部转向平滑

头部不会瞬间转向目标方向，而是以 8% 的速率渐进转向（`HEAD_TURN_RATE = 0.08`）。这个参数经过反复调试——太快则显得机械，太慢则反应迟钝。8% 刚好让转向看起来像是"思考后决定的方向调整"而非"程序强制对齐"。

## 视觉渲染

### 七层渲染管线

每一帧，深渊螈的渲染按以下顺序执行，后绘制的层覆盖先绘制的层：

```
1. 身体光晕 (BodyGlow)   — 大范围低透明度光圈，营造荧光氛围
2. 身体轮廓 (Body)        — 基于脊柱法线生成的实体形状
3. 肢体 (Limbs)           — 关节连线 + 关节圆点 + 脚部脉冲
4. 脊柱细节 (SpineDetails)— 发光斑点 + 横纹条纹
5. 头部 (Head)            — 椭圆形头部 + 内层高光
6. 眼睛 (Eyes)            — 眼白 + 瞳孔 + 脉冲光晕
7. 外鳃 (Gills)           — 贝塞尔曲线绘制的呼吸器官
```

### 身体轮廓生成

身体不是一串圆形，而是由脊柱法线方向偏移生成的闭合多边形。对每个脊椎节段，计算其运动方向的垂直方向（法线），向左右各偏移该节段的宽度值，得到左右两组轮廓点。连接左轮廓 + 反向右轮廓，形成完整的身体形状。

内层再以 50% 宽度绘制一个半透明高光层，模拟腹部的反光——这让身体有了体积感而非扁平感。

### 发光斑点与横纹

沿脊柱每隔一节绘制脉冲发光斑点，色相随时间缓慢漂移（±40°），模拟深海生物的荧光细胞。每个节段还绘制一条垂直于脊柱方向的细椭圆横纹，低透明度叠加，模拟皮肤的纹理节奏。

### 外鳃的贝塞尔曲线

3 对外鳃附着在脊柱第 2~4 节两侧，每根鳃由一条三次贝塞尔曲线绘制。控制点的偏移量随正弦函数波动，模拟呼吸的节奏。鳃的根部从身体轮廓边缘出发，尖端向外展开——这是深渊螈最具辨识度的视觉特征。

### 粒子系统

两种粒子源共同营造氛围：

- **环境浮游粒子**：每帧在画布随机位置生成 3 个，极慢速漂移，模拟深水中的浮游生物。色相随时间在青蓝色域缓慢波动
- **尾迹粒子**：每 3 帧从尾尖释放 1 个，带有随机偏移和衰减，形成游动轨迹
- **惊吓粒子**：惊吓状态下每 2 帧从头部释放 2 个红色粒子，强化逃跑的戏剧性

粒子上限 200 个，生命周期 40~100 帧，尺寸随生命衰减。整个系统用 `splice` 从后向前遍历删除，避免索引错位。

### 行为状态指示器

头部上方有一个小光点，颜色对应当前状态——青蓝（漫游）、橙色（追踪）、红色（惊吓）、暗紫（休息）。这是给观察者的视觉提示，让你能直观理解"它现在在想什么"。

## 架构设计

### 引擎与渲染的严格分离

这是整个项目最重要的架构决策。

```
引擎层（零外部依赖）
  ├── vec2.ts           二维向量数学库
  ├── types.ts          类型定义
  ├── spine.ts          脊柱链式运动
  ├── limb.ts           肢体二关节 IK
  ├── behavior.ts       行为状态机
  └── creature.ts       生物组合与更新

渲染层
  ├── particles.ts      粒子系统
  └── creatureRenderer.ts  生物渲染器

桥接层
  └── sketch.ts         p5.js sketch 桥接
```

**引擎层不调用任何绘图 API**。`spine.ts` 不知道什么是 `ellipse()`，`behavior.ts` 不知道什么是 `fill()`。引擎只做计算：输入位置和参数，输出新的位置和参数。

**为什么这很重要？**

1. **可移植**：引擎层可以原封不动地搬到 Canvas 2D、WebGL、甚至终端字符界面——只需重写渲染层
2. **可测试**：可以脱离 p5.js 对引擎逻辑做单元测试，验证"距离约束是否正确"、"IK 解是否合理"
3. **可推理**：阅读引擎代码时不需要理解任何渲染细节，行为逻辑是自明的

**快照模式**：`getCreatureSnapshot()` 在每帧创建一份深拷贝的不可变快照传给渲染层。渲染层拿到的是纯数据，不会反向修改引擎状态。这保证了数据流的单向性：引擎 → 快照 → 渲染。

### 向量库的设计

`vec2.ts` 提供了 17 个纯函数，所有操作返回新对象而非修改输入。这是不可变数据风格的体现——虽然引擎内部使用可变状态（脊柱位置需要原地更新），但向量运算本身是无副作用的，避免了"谁在什么时候改了这个值"的追踪难题。

## 交互设计

### 三层交互模型

| 层级 | 方式 | 效果 |
|------|------|------|
| **感知** | 鼠标在画布内移动 | 生物感知鼠标位置，距离 300px 内进入追踪状态 |
| **触发** | 鼠标突然靠近（< 80px） | 生物惊吓，快速反向逃离 |
| **指令** | 点击画布任意位置 | 生物立即切换到追踪状态，朝点击位置移动 |

**为什么不用拖拽？** 拖拽意味着"用户控制生物的头部位置"，这会破坏行为系统的自主性——深渊螈变成了提线木偶。而"点击设定目标"保留了生物的自主决策权：它决定怎么走过去，你只决定它往哪走。

**鼠标感知的细节**：鼠标位置在画布内时始终传递给引擎（即使未按下），这让生物能"注意到"你的存在。按下鼠标时则强制传递，确保点击交互的可靠性。

## 设计哲学

### 规则驱动，而非帧驱动

深渊螈的每一帧画面都不是"画出来的"，而是"算出来的"。我定义了脊柱如何跟随、腿如何迈步、情绪如何切换，然后让系统自己表演。这意味着每次运行都可能是不同的——漫游的方向是随机的，休息的时机是概率的，惊吓的反应是实时的。

### 算法是工具，不是教条

设计文档提供了多种算法方向，我没有拘泥于任何一种，而是混合使用：

- 脊柱 = 距离约束迭代法（思路 A）+ 角度约束法（思路 D）
- 肢体 = 二关节解析法（思路 A）+ 脚吸附释放法（思路 D）
- 行为 = 状态机（思路 D）+ 随机漫游（思路 A）
- 渲染 = 程序形状生成（思路 B）+ 粒子装饰（思路 C）

每种算法都在它最擅长的位置发挥作用。

### 先让它活，再让它美

实现顺序是：脊柱跟随 → 肢体行走 → 行为漫游 → 视觉渲染 → 粒子氛围。每一步都先确保"它能动"，再考虑"它好看"。一个能走但不好看的生物，比一个好看但不会走的生物更有价值——因为前者可以迭代优化，后者只是静态的装饰。
