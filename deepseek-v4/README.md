# 翡翠蜈蚣 · Jade Centipede

> **一段代码，一个活生生的世界。**
>
> 这不是一段动画——这是一条由算法驱动的生命。

---

## 一眼概览

一条 28 节翡翠色的蜈蚣在幽暗的深林地面上蜿蜒爬行。它的身体像波浪一样起伏前进，56 条腿交替迈步，触角轻轻摆动，头部发出微弱的荧光。你可以点击画布，它会朝你的指尖追逐而来；你松开鼠标，它便恢复漫游，在休憩、探索和游走之间自如切换。

这不是预渲染的视频，不是逐帧动画。这是一条**纯程序化生成的生命**——每一帧都由数学和算法实时计算。

## 灵感来源

我从小喜欢观察虫子。

小时候蹲在院子里看蚂蚁搬家，看蜈蚣在石缝间穿梭——它们的身体像一列微型火车，每一节都在重复同样的动作，但整体形成一种令人着迷的波浪。蜈蚣的运动有一种独特的韵律美：它不像蛇那样完全靠身体扭动，也不像昆虫那样只有六条腿，它是两者的完美融合——无数条腿在身体两侧交替迈动，形成一道连绵不绝的"腿浪"。

**我想在屏幕上复现这种美。**

不是通过动画师一帧一帧地绘制，而是通过算法——定义规则，让代码自己"表演"。就像真实的蜈蚣一样，它的每一个动作都不是预先设计好的，而是对环境的实时响应。

## 核心算法

### 脊柱——距离约束迭代法

蜈蚣的 28 节身体使用**双向距离约束迭代**算法：

1. 头部朝目标移动
2. 从头部到尾部依次向前推，保持每节之间的固定距离
3. 从尾部到头部依次向后拉，修正累积的误差
4. 重复 4 次迭代，每次误差减半

```
蛇形运动的精髓：每一节都在追随前一节，
而前一节又在追随更前一节，
最终整个身体形成连贯的波浪。
```

我还为脊柱添加了**横向摆动**——每节身体会有一个微小的正弦偏移，让运动看起来更像真实蜈蚣的"S"形前进。

### 肢体——二关节解析 IK

每条腿由两个关节组成（类比大腿+小腿），使用**解析 IK**（反向运动学）计算：

- 已知肩部位置、脚部目标、两段腿的长度
- 用余弦定理直接算出膝盖位置
- 支持左/右镜像（膝盖朝向相反方向）
- 计算一次即得解，无需迭代

这比数值迭代法快得多，而且对于二关节结构来说精度完全足够。

### 步态——脚吸附/释放 + 波浪步态

蜈蚣的步态是我最自豪的部分。它结合了两种机制：

**脚吸附/释放**：

- 脚着地时（planted），固定在地面不动，身体从上方走过
- 当身体移动太快，脚与肩部的距离超过阈值时，脚抬起向前迈步
- 脚在空中画出一条弧线（用 `sin` 控制抬脚高度），然后重新着地

**交替波浪步态**：

- 左右腿相位差 180°（左侧迈步时右侧着地）
- 沿身体从前到后，每条腿有递增的相位偏移
- 结果：腿从前往后依次抬起和放下，形成连绵的"腿浪"

这正是真实蜈蚣的步态模式！如果你观察过蜈蚣走路，会发现它的腿不是同时动的，而是从头部向尾部依次波动。

### 行为系统——状态机

生物有四种行为状态，自动切换：

| 状态 | 触发条件 | 行为表现 |
|---|---|---|
| **漫游** | 默认状态 | 随机选目标，缓慢移动 |
| **追逐** | 用户点击画布 | 1.3 倍速冲向点击位置 |
| **休憩** | 随机触发 | 在原地轻微晃动，休息 1-3 秒 |
| **探索** | 随机触发 | 用噪声函数生成弯曲路径，探索周围 |

行为切换有完整的时机控制——不会频繁切换导致动作不自然，也不会长时间不切换显得无聊。

## 视觉设计

### 翡翠配色

全身采用翡翠绿渐变：头部鲜绿 → 尾部青蓝。每个节段都有两层椭圆叠加（主体 + 高光），配合呼吸般的缩放动画，让身体看起来有生命感。

### 鳞甲纹理

每隔一节的身体上绘制了交叉的菱形纹路，像蜈蚣的甲壳节片。纹路的透明度随时间闪烁，模拟光线在甲壳上的反射。

### 发光眼睛

头部有两只三层结构的眼睛：
- 外层：扩散的光晕
- 中层：主瞳孔
- 内层：高光点

眼睛的亮度随时间脉动，像真正的生物在呼吸。

### 触角

两条触角从头部伸出，每帧动态计算弯曲路径，叠加了多层正弦波——让触角看起来像在空气中轻轻探索。

### 粒子特效

- **尾部拖尾**：最后一节身体不断释放发光粒子，粒子逐渐淡出，形成轨迹
- **脚步溅射**：腿抬离地面时溅起小光点

### 环境

深色渐变背景（墨绿到黑色），点缀了 30 颗微弱闪烁的星点——给整个场景一种"深夜的森林地表"的氛围。

## 交互设计

| 操作 | 效果 |
|---|---|
| **点击画布** | 蜈蚣切换为「追逐」状态，朝点击位置快速移动 |
| **松开鼠标** | 恢复自主漫游 |
| **节段滑块** | 调整身体节段数（10-40），实时生效 |
| **速度滑块** | 调整移动速度（30-200），实时生效 |
| **隐藏/显示面板** | 切换右侧控制面板 |

交互遵循"立即反馈"原则：
- 点击瞬间出现脉动十字准星指示器
- 行为切换时头部上方显示中文状态标签
- 控制面板实时高亮当前行为
- 左上角始终显示节段数、速度、状态的调试信息

## 架构设计

严格遵循**引擎与渲染分离**架构：

```
deepseek-v4/src/
├── engine/           # 引擎层——纯算法，无任何绘图调用
│   ├── types.ts      # 类型定义（Vec2、CreatureConfig、BehaviorType 等）
│   ├── math.ts       # 向量运算工具（add/sub/normalize/lerp 等）
│   ├── spine.ts      # 脊柱链式运动（距离约束迭代法）
│   ├── leg.ts        # 肢体 IK（二关节解析法 + 脚吸附/释放）
│   ├── behavior.ts   # 行为状态机（漫游/追逐/休憩/探索）
│   └── creature.ts   # 生物创建和更新调度
├── render/           # 渲染层——p5.js 可视化
│   └── creatureRender.ts  # 全部绘图逻辑
├── components/
│   └── BioCanvas.tsx  # React 桥接层
├── App.tsx            # 主 UI
└── main.tsx           # 入口
```

**关键原则**：
- 引擎层不调用任何绘图 API，不依赖 p5.js
- 引擎通过参数接收数据，通过返回值/直接修改数据结构输出
- 渲染层只负责画，不参与任何运动学计算
- 更换渲染技术（Canvas 2D、WebGL、Three.js）只需替换 render/ 目录

## 一点思考

在实现这个项目的过程中，我最大的体会是：**程序化动画的魅力不在于代码本身，而在于观察结果时那种"它活了"的感觉。**

当我把蜈蚣的腿浪步态调好，第一次看到那 56 条腿从前往后依次波动的时候，我真的愣了几秒——不是因为代码写得多漂亮，而是因为屏幕上那个东西看起来确实像一条活着的蜈蚣。

这种从算法中涌现出"生命感"的瞬间，就是做这个项目最大的动力。

> *每条腿都不知道其他腿在做什么，*
> *整个身体也不知道自己要去哪里，*
> *但合在一起，它看起来就像是有自己的想法。*
>
> ——这就是程序化动画的诗意。
