# 性能建议

如果你的动画开始变慢，可以尝试这些方向。但记住：**先让它跑起来，再优化！**

---

## 什么时候需要优化？

- 帧率明显下降（低于 30fps）
- 生物数量增加时明显变慢
- 移动时感觉卡顿
- 风扇开始狂转（功耗问题）

---

## 优化方向一：减少计算量

### 思路 A：降低迭代次数

很多算法是迭代的，迭代次数越多越精确，但也越慢。

**可以尝试的**：
- 距离约束：从 5 次降到 3 次，甚至 2 次
- IK 求解：减少迭代次数
- 观察效果：有时候减少一点精度，视觉上差别不大，但快很多

---

### 思路 B：简化生物复杂度

**可以尝试的**：
- 减少脊柱节段数量（比如从 30 降到 15）
- 减少肢体数量（比如从 8 条腿降到 4 条）
- 用更简单的算法替代复杂算法（视觉上差不多就行）

---

### 思路 C：不是每帧都算所有东西

有些东西不需要每帧都更新。

**可以尝试的**：
- 每 2 帧更新一次漫游目标选择
- 不是每帧都重新计算所有肢体，可以交替更新
- 距离远的生物可以用简化的更新逻辑

---

## 优化方向二：减少对象创建

频繁创建新对象会导致垃圾回收，造成卡顿。

### 思路 A：对象复用

创建一个对象池，需要时取出来，用完放回去。

```
不需要的：
  每帧都创建新的坐标对象

可以尝试的：
  有一个坐标对象池
  需要时从池里拿一个
  用完重置一下放回去
```

---

### 思路 B：直接修改数据，不创建新对象

有些数据可以直接修改，而不是每次都创建新的。

```
注意：这会让状态管理变复杂，
所以要权衡：简单 vs 性能

先让代码简单清晰，
真的需要时再做这个优化。
```

---

## 优化方向三：渲染优化

渲染通常也是瓶颈之一。

### 思路 A：简化绘制

**可以尝试的**：
- 用简单的图形代替复杂的图形
- 减少透明效果（可能慢）
- 减少描边或装饰性元素
- 距离远的生物用更简单的渲染方式

---

### 思路 B：不要重画整个画面

如果只需要局部更新，就只更新那一块。

**可以尝试的**：
- 只重画变化的区域（但这通常比较复杂）
- 静态背景只画一次，之后不再重画

---

## 优化方向四：多生物时的策略

### 思路 A：生物数量限制

设定一个合理的上限。

```
可以尝试的：
  - 默认限制 20 个生物
  - 超过后提示用户可能会慢
  - 或者自动降低远处生物的复杂度
```

---

### 思路 B：远近分级

距离近的生物用精细算法和渲染，距离远的简化。

```
可以尝试的：
  距离近 → 完整算法 + 精细渲染
  距离中 → 简化算法 + 简单渲染
  距离远 → 超简化算法 + 最少渲染
```

---

### 思路 C：休眠策略

不是活动状态的生物可以"休眠"，更新频率降低。

```
可以尝试的：
  - 被选中的生物 → 每帧更新
  - 在动的生物 → 每帧更新
  - 不动的、远处的 → 每 N 帧更新一次
```

---

## 优化方向五：架构层面

### 思路 A：分离更新和渲染

更新逻辑和渲染逻辑分开，方便各自优化。

```
好处：
  - 可以用不同的帧率（比如更新 30fps，渲染 60fps）
  - 可以把更新逻辑和渲染逻辑放不同线程（如果平台支持）
```

---

### 思路 B：数据布局优化

把常一起访问的数据放在一起。

```
（这是比较进阶的优化，
  通常不需要一开始就考虑）
```

---

## 优化的科学方法

### 第一步：测量

先搞清楚慢在哪里，不要瞎优化。

```
可以尝试的工具/方法：
  - 帧率显示
  - 性能分析器（profile）
  - 简单计时：看看每部分花了多少毫秒
```

### 第二步：找瓶颈

找出最花时间的部分。

```
常见的瓶颈：
  - 某算法太复杂
  - 渲染太慢
  - 频繁创建对象
  - 没有必要的重复计算
```

### 第三步：优化瓶颈

只优化那个最慢的部分，其他地方先别动。

### 第四步：再次测量

看看优化有没有效果，效果够不够。

---

## 什么时候不要优化

### 还不够慢的时候
- 帧率已经 60fps 了，就别瞎优化了
- 保持代码简单清晰更重要

### 还不知道瓶颈在哪里的时候
- 不要凭感觉优化
- 先测量，找到瓶颈

### 优化会让代码变得很乱的时候
- 权衡：性能提升 vs 代码复杂度
- 有时候稍微慢一点，但代码简单易懂，是值得的

---

## 简单的性能检查清单

- [ ] 帧率是否稳定（30fps 以上通常可以接受）
- [ ] 生物数量增加时，性能下降是否可接受
- [ ] 有没有明显的卡顿（尤其是突然卡一下）
- [ ] 设备发热或耗电是否严重

---

## 最后的建议

**先让它工作，再让它快！**

1. 先用简单的方式实现，让东西跑起来
2. 观察性能，看看够不够好
3. 如果不够好，测量找到瓶颈
4. 优化瓶颈部分
5. 重复这个过程

性能优化是一个渐进的过程，很少需要一开始就做到完美。
