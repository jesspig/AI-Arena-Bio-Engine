# 性能优化策略

## 1. 优化目标

系统需要在保持 60 FPS 帧率的前提下，同时渲染多个程序化生物。优化策略涵盖 React 端、p5 端和内存管理三个维度。

## 2. React 端优化

### 2.1 React.memo 应用

```mermaid
graph TD
    A[组件渲染] --> B{使用 React.memo?}
    B -->|是| C{props 浅比较变化?}
    B -->|否| D[总是重新渲染]
    C -->|是| D
    C -->|否| E[跳过渲染]
```text

#### 2.1.1 memo 包裹策略

| 组件 | 是否使用 memo | 原因 |
| --- | --- | --- |
| Layout | 否 | 布局稳定，子组件变化时总会渲染 |
| Sidebar | 是 | 仅在 selectedId 变化时更新 |
| CanvasPanel | 是 | 避免 creatures 数组未变化时重渲染 |
| CreatureList | 是 | 仅在 creatures 数组引用变化时更新 |
| CreatureListItem | 是 | 仅在对应生物状态变化时更新 |

#### 2.1.2 性能收益

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 添加新生物 | 所有组件重新渲染 | 只有 CreatureList 和 CanvasPanel 渲染 |
| 选中生物 | 所有组件重新渲染 | 只有 Sidebar 和 CreatureListItem 渲染 |
| 参数调整 | 所有组件重新渲染 | 只有 Sidebar 和 CanvasPanel 渲染 |

### 2.2 useCallback 优化

| 回调函数 | 依赖项 | 优化效果 |
| --- | --- | --- |
| handleSelect | dispatch | 避免每次渲染创建新函数引用 |
| handleRemove | dispatch | 避免每次渲染创建新函数引用 |
| sketch 函数 | creatures, selectedId, dispatch | 避免 p5 实例频繁重建 |

#### 2.2.1 useCallback 原理

```mermaid
graph TD
    A[组件渲染] --> B{useCallback 依赖变化?}
    B -->|是| C[创建新回调函数]
    B -->|否| D[返回缓存的回调函数]
    C --> E[子组件可能重新渲染]
    D --> F[子组件跳过渲染（配合 memo）]
```mermaid

### 2.3 dispatch 传递优化

| 传递方式 | 引用稳定性 | 重渲染风险 |
| --- | --- | --- |
| 传递整个 context value | 每次状态变化都创建新对象 | 高 |
| 单独传递 dispatch | dispatch 引用始终稳定 | 低 |

**推荐方式**：单独传递 dispatch，配合 memo 实现精确渲染控制。

## 3. p5 端优化

### 3.1 对象复用

#### 3.1.1 Vec2 对象池

```mermaid
graph TD
    A[每帧需要坐标计算] --> B{使用对象池?}
    B -->|是| C[从池中获取空闲 Vec2]
    B -->|否| D[创建新 Vec2 对象]
    C --> E[使用后归还到池]
    D --> F[增加 GC 压力]
```text

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 每帧创建新对象 | 代码简单 | GC 压力大，可能卡顿 |
| 对象池复用 | 降低 GC 压力 | 需要管理池状态 |

#### 3.1.2 适用场景

| 场景 | 对象分配频率 | 推荐方案 |
| --- | --- | --- |
| 方向向量计算 | 每帧多次 | 对象池 |
| 临时坐标存储 | 每帧多次 | 对象池 |
| 生物配置对象 | 状态变化时 | 正常创建 |

### 3.2 迭代次数控制

| 参数 | 推荐值 | 原因 |
| --- | --- | --- |
| constraintIterations | 3 | 平滑性和性能的最佳平衡 |
| spineCount | ≤ 20 | 节点过多增加计算量 |
| legCount | ≤ 6 | 腿部过多增加 IK 计算量 |

### 3.3 draw 循环优化

#### 3.3.1 避免操作

| 操作 | 原因 | 替代方案 |
| --- | --- | --- |
| 频繁创建对象 | 增加 GC 压力 | 对象池复用 |
| 复杂数学运算 | 计算开销大 | 查表或预计算 |
| DOM 操作 | 跨线程通信 | 避免在 draw 中操作 DOM |
| 网络请求 | 异步阻塞 | 在外部处理 |

#### 3.3.2 推荐操作

| 操作 | 原因 |
| --- | --- |
| 读取已缓存的状态 | 无额外开销 |
| 简单数学运算 | 计算量小 |
| p5 绘图 API 调用 | 原生优化 |

## 4. 内存管理

### 4.1 生物删除清理

```mermaid
flowchart TD
    A[REMOVE_CREATURE Action 触发] --> B[Reducer 过滤 creatures 数组]
    B --> C[p5 中对应的 Creature 实例]
    C --> D[从 Creature 数组中移除引用]
    D --> E[等待 GC 回收]
    E --> F[无悬挂引用残留]
```text

#### 4.1.1 清理检查项

| 检查项 | 说明 |
| --- | --- |
| Creature 数组引用 | 确保从 p5 的 Creature 数组中移除 |
| 定时器 | 若有定时器，必须清除 |
| 事件监听器 | 若注册了事件监听器，必须移除 |
| useRef 管理 | 确保 useRef 中无残留引用 |

### 4.2 组件卸载清理

| 资源类型 | 清理方式 |
| --- | --- |
| p5 实例 | @p5-wrapper/react 自动调用 remove() |
| DOM 节点 | React 自动清理 |
| 事件监听器 | useEffect cleanup 函数移除 |
| 定时器 | useEffect cleanup 函数清除 |

### 4.3 内存泄漏预防

| 潜在泄漏点 | 预防措施 |
| --- | --- |
| 闭包引用 | 确保闭包不引用已删除的生物 |
| 定时器未清除 | 组件卸载时清除所有定时器 |
| 事件监听未移除 | 组件卸载时移除所有监听器 |
| p5 实例残留 | 使用 @p5-wrapper/react 自动管理 |

## 5. 对象池模式

### 5.1 适用场景

当生物数量超过 20 个时，建议采用对象池模式管理 Creature 实例生命周期。

### 5.2 对象池架构

```mermaid
classDiagram
    class CreaturePool {
        +Creature[] active
        +Creature[] inactive
        +create(config): Creature
        +release(creature): void
        +updateAll(): void
    }
    
    class Creature {
        +boolean active
        +update(): void
    }
    
    CreaturePool --> Creature
```mermaid

### 5.3 对象池流程

```mermaid
flowchart TD
    A[需要新生物] --> B{inactive 池有空闲?}
    B -->|是| C[从 inactive 池取出]
    B -->|否| D[创建新 Creature 实例]
    C --> E[重置配置]
    D --> E
    E --> F[添加到 active 池]
    
    G[删除生物] --> H[从 active 池移除]
    H --> I[添加到 inactive 池]
    I --> J[标记为 inactive]
```mermaid

### 5.4 对象池优势

| 优势 | 说明 |
| --- | --- |
| 减少创建开销 | 复用已有实例，避免频繁创建 |
| 降低 GC 压力 | 不产生垃圾对象 |
| 性能稳定 | 避免 GC 导致的帧率波动 |

## 6. 性能监控

### 6.1 关键指标

| 指标 | 目标值 | 监控方式 |
| --- | --- | --- |
| 帧率 FPS | ≥ 60 | requestAnimationFrame 时间戳 |
| 生物数量 | ≤ 20（无对象池） | 状态数组长度 |
| 内存占用 | 稳定增长 | 浏览器 DevTools Memory |
| GC 频率 | 低频 | 浏览器 DevTools Performance |

### 6.2 性能测试场景

| 场景 | 生物数量 | 预期 FPS |
| --- | --- | --- |
| 单生物 | 1 | 60 |
| 中等负载 | 10 | 60 |
| 高负载 | 20 | 55~60 |
| 极限负载 | 50 | 依赖硬件 |

## 7. 优化建议总结

### 7.1 必做优化

| 优化项 | 实施难度 | 效果 |
| --- | --- | --- |
| React.memo 包裹组件 | 低 | 减少不必要重渲染 |
| useCallback 缓存回调 | 低 | 避免函数引用变化 |
| 单独传递 dispatch | 低 | 稳定引用，减少渲染 |
| 控制迭代次数为 3 | 无 | 平衡精度和性能 |

### 7.2 推荐优化

| 优化项 | 实施难度 | 效果 |
| --- | --- | --- |
| Vec2 对象池 | 中 | 降低 GC 压力 |
| 生物数量限制 | 低 | 防止性能崩溃 |
| draw 循环避免对象创建 | 中 | 稳定帧率 |

### 7.3 可选优化

| 优化项 | 实施难度 | 效果 |
| --- | --- | --- |
| 完整对象池模式 | 高 | 大规模生物场景 |
| 三角函数查表 | 中 | 加速 IK 计算 |
| Web Worker 分离计算 | 高 | 主线程专注渲染 |
