# 生物引擎（Bio-Engine）项目概述

## 1. 项目简介

生物引擎是一个基于 React 和 p5.js 的程序化生物动画系统，用于创建和展示具有自然运动行为的虚拟生物。系统通过参数化配置和算法驱动，实现多生物并行管理、手动操控与自主漫游功能，适用于游戏开发、艺术装置及教育演示等场景。

## 2. 系统定位与核心价值

### 2.1 系统定位

- **类型**：前端动画引擎
- **目标用户**：开发者、设计师、教育工作者
- **核心价值**：提供可扩展的程序化生物动画底层工具原型

### 2.2 关键特性

- 多生物并行管理与动画渲染
- 支持手动控制与自主漫游两种行为模式
- 高度参数化配置，无需修改核心代码即可调整生物形态和行为
- 基于 p5.js 实例模式，避免全局作用域污染
- 支持多画布同时运行

## 3. 技术栈与框架整合决策

### 3.1 核心技术选型

| 技术领域 | 选型方案 | 版本 | 决策依据 |
| --- | --- | --- | --- |
| 前端框架 | React | 19.x | 2024/12 稳定发布，Actions/useOptimistic 等新 API 生产就绪 |
| 编程语言 | TypeScript（严格模式） | 5.8.x | 类型安全，`strict: true`，7.0 在 beta 阶段 |
| 动画引擎 | p5.js（实例模式） | 1.11.x | 推荐 1.x 稳定版，2.x 预计 2026/08 前保持 1.x 为默认 |
| p5 集成 | @p5-wrapper/react | ^5.0.3 | 要求 react≥19.0.0，重构类型系统，移除 `as` 类型断言 |
| 状态管理 | React Context + useReducer | 内置 | 时间旅行能力，无需外部库 |
| 样式方案 | Tailwind CSS | 4.x | 原子化 CSS，自动内容检测，5× 构建加速 |
| 构建工具 | Vite | 6.x | Node 18/20/22+ 支持，Vite 6 于 2024/11 发布 |

### 3.2 框架整合模式对比分析

在 2026 年 React 应用中集成 p5.js 存在三种主流方案：

#### 方案 A：纯手工 Wrapper 方案

- **实现方式**：利用 `useEffect` 与 `useRef` 钩子直接编写 p5.js 集成逻辑
- **优点**：对所有行为控制最为精细，初学者友好
- **缺点**：需要手动实现重复逻辑，维护成本较高

#### 方案 B：第三方组件库方案

- **代表组件**：@p5-wrapper/react、@korkje/p5-react
- **优点**：提供现成组件包裹器，自动处理实例清理、Props 传递
- **适用场景**：快速开发，减少样板代码

#### 方案 C：@p5-wrapper/react v5 核心机制

- **核心特性**：
  - `updater` prop 桥接 React 状态到 p5 生命周期
  - 重构内部类型系统，消除所有 `as` 类型断言
  - sketch prop 机制传递 p5 函数

### 3.3 最终决策：方案 C + 自定义 Hook 组合

**决策**：采用 @p5-wrapper/react ^5.0.0 配合自定义 Hook

**决策依据**：

1. 利用 `<P5Canvas>` 组件自动完成 p5 实例生命周期管理，无需开发者手动实现重复逻辑
2. 通过 v5 的 `updater` prop 建立 React 状态到 p5 生命周期的单向数据桥，保持 sketch 逻辑纯净
3. 通过自定义 Hook（如 `useCreatureSketch`）将生物配置数据、状态更新逻辑、鼠标事件处理等封装为可复用的函数
4. 与 React 组件解耦，实现清晰的分层架构
5. 该方案在保持开发者对动画逻辑的完全掌控的同时，最小化了框架间的版本冲突与破坏性更新风险

**架构层次说明**：

- **界面层**：由 React 组件构成的 UI 面板和画布容器，负责用户输入、参数传递与列表展示
- **状态管理层**：基于 React Context 与 useReducer 管理的全局不可变状态
- **适配层**：React 端与 p5 端之间的桥梁，自定义 Hook 和事件回调
- **引擎层**：纯逻辑类，无任何框架依赖，负责核心算法执行

## 5. 项目文件结构

```text
src/
├── engine/              # 引擎层（纯逻辑，无框架依赖）
│   ├── Creature.ts      # 生物主体：数据聚合与行为编排
│   ├── Spine.ts         # 脊柱链式约束：距离约束求解、头部追逐
│   └── Leg.ts           # 反向运动学（IK）：二关节解析求解、贴地逻辑
├── state/               # 状态管理层
│   ├── CreatureContext.tsx  # Context Provider 与 Hook 导出
│   └── reducer.ts       # useReducer 纯函数 + Action 定义
├── hooks/               # 适配层
│   └── useCreatureSketch.ts  # 封装 sketch 函数与交互回调
├── components/          # 界面层
│   ├── Layout.tsx       # 三列布局容器
│   ├── CanvasPanel.tsx  # p5 画布容器（P5Canvas 包装）
│   ├── Sidebar.tsx      # 左侧配置面板（滑块、按钮、创建/删除）
│   └── CreatureList.tsx # 右侧生物列表（选中、删除）
├── types/               # 类型定义
│   └── creature.ts      # CreatureConfig、SpineNode 等共享类型
└── App.tsx              # 应用入口
```text

**目录职责说明**：

- **engine/**：纯 TypeScript 类，不含任何框架依赖，可独立移植
- **state/**：全局状态管理，使用纯函数 reducer，易于测试
- **hooks/**：React 自定义 Hook，封装 p5 sketch 函数逻辑
- **components/**：纯 UI 组件，使用 React 和 Tailwind CSS
- **types/**：共享类型定义，确保跨模块类型安全

## 6. 技术债务控制

本项目遵循零技术债务原则：

- 同一功能只保留一种实现
- 旧代码重构后立即删除
- 不保留注释掉的代码块
- 不添加 `@deprecated` 标记等待清理
- VCS 作为历史记录的保留，代码库中只保留当前实现
